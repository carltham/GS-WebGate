## Implementation Guidelines

### SwingWorker Implementation

```java
public class AnalysisWorker extends SwingWorker<AnalysisReport, AnalysisProgressEvent> {
    
    @Override
    protected AnalysisReport doInBackground() throws Exception {
        // Background thread work
        for (File file : files) {
            analyze(file);
            
            // Publish progress on EDT
            AnalysisProgressEvent progress = new AnalysisProgressEvent(...);
            publish(progress);
            
            if (isCancelled()) {
                break;
            }
        }
        return report;
    }
    
    @Override
    protected void process(List<AnalysisProgressEvent> chunks) {
        // Called on EDT with published events
        for (AnalysisProgressEvent event : chunks) {
            fireProgressListener(event);
        }
    }
    
    @Override
    protected void done() {
        // Called on EDT after completion
        try {
            AnalysisReport result = get();
            fireCompletionListener(result);
        } catch (CancellationException e) {
            fireErrorListener("Analysis cancelled");
        }
    }
}
```

### Controller Threading Pattern

```java
public class AnalysisController {
    private AnalysisWorker worker;
    
    public void startAnalysis(ProjectMetadata project) {
        if (worker != null && !worker.isDone()) {
            return; // Already running
        }
        
        worker = new AnalysisWorker(project);
        worker.execute(); // Runs in background
    }
    
    public void cancelAnalysis() {
        if (worker != null) {
            worker.cancel(true); // Interrupt if needed
        }
    }
}
```

### EDT Safety Rule

NEVER block EDT:
```java
// WRONG - blocks EDT
analysisResult = blockingServiceCall();

// RIGHT - background thread handles blocking
worker.doInBackground() {
    return blockingServiceCall();
}
```

## Common Issues

### Thread Pool Exhaustion
- Limit concurrent workers
- Properly clean up after completion

### Event Listener Memory Leaks
- Remove listeners when not needed
- Use WeakReferences if appropriate

### Progress Event Queue
- Don't fire too many events (batching)
- Update UI 10-20 times per second max
