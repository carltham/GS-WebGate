## Key Concepts

### Threading Strategy

Phase 2 introduces background threading:
- **Main Thread (EDT):** Updates UI only
- **Worker Thread:** Runs analysis (via SwingWorker)
- **Event Dispatch:** Progress updates via EDT

**Critical Rule:** Never block EDT with long operations!

### SwingWorker Pattern

```java
public class AnalysisWorker extends SwingWorker<AnalysisReport, AnalysisProgressEvent> {
    @Override
    protected AnalysisReport doInBackground() {
        // Runs in background thread
        // Call publish() to fire progress events
    }
    
    @Override
    protected void done() {
        // Runs on EDT after background work
    }
}
```

### EDT Safety

Use `SwingUtilities.invokeLater()` for UI updates:
```java
SwingUtilities.invokeLater(() -> {
    // UI updates here
});
```

## Important Notes

### Testing Challenges

Phase 2 testing is tricky because of threading:
- Use `CountDownLatch` to wait for background work
- Mock SwingUtilities if needed
- Test events, not threads directly

### Thread Safety

Ensure:
- Mutable fields use `volatile` or synchronization
- No race conditions
- Proper cleanup after cancel

### EDT Rule

Never call blocking operations on EDT:
```java
// WRONG - blocks EDT
EDT: analysisResult = blockingServiceCall(); 

// RIGHT - background thread does work
Worker: analysisResult = blockingServiceCall();
EDT: displayResult(analysisResult);
```
