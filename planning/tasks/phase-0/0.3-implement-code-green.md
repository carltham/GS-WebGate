## Implementation Guidelines

### Key Principle: Minimal & Direct

Each class should:
1. Do ONE thing
2. Have minimal methods
3. No unnecessary complexity
4. Just enough to pass tests

### Layer Separation

- **UI Components** (panels, windows) - NO business logic
- **Data** (DTOs) - Simple value holders
- **Controllers** - In later phases

For Phase 0, keep it simple:
```
UI Components
└─ Show data
└─ No logic
```

### Test-Driven Implementation

For each failing test:
1. Read test requirement
2. Implement minimal code to pass
3. Run test
4. Verify it passes
5. Move to next test
